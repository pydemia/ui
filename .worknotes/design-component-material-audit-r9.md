# Chosen20 component material audit (R9)

2026-10-15 · read-only source audit · baseline `0b1dec2b` / `codex/design-component-harmony`

## Scope and guardrails

Audited `packages/ui/src/components` only. Basic remains the baseline and must render unchanged; PRISM remains outside the design-mode surface and must remain unchanged. The other worker owns textbox primitives/composites (Input, Textarea, Select-like input composition); this note covers the adjacent prompt/thread/forms/editor shells and the named controls, menus, navigation, panels, tables, tree, filters, log viewer, pagination, and node canvas. At audit time no source/build/Git/browser changes were made; the later DOM-attribute-only implementation is recorded in the addendum below.

The chosen20 material/token layer is in `packages/ui/src/design-modes.css`. Its hooks currently cover button, input/textarea/select-trigger/native-select, badge, card, heading, overlay-panel, drawer-panel, app-shell, dashboard recipes; plus global table and switch/checkbox role selectors and a progressbar selector (`design-modes.css:327–490`). **Correction:** `apps/docs/src/styles.css:1–3` imports Tailwind first, whose utilities are in `@layer utilities`; `packages/ui/src/design-modes.css` is imported unlayered from `apps/docs/src/main.tsx:20`. Normal unlayered declarations outrank normal layered declarations regardless of specificity, so the prior claim that Tailwind utilities defeat design-mode rules was wrong and is retracted. The zero-specificity `:where(...)` selectors can matter when competing with other unlayered rules, not with Tailwind utilities. `styles.css:189–205` maps Tailwind radius utilities through `--radius`; the mode layer also has richer `--control-radius`, `--field-radius`, and `--panel-radius-material` roles. Hook gaps below refer to missing mode-role coverage, not proven Tailwind cascade failures.

**Corrected CSS contract:** do not raise specificity across the board. For package utilities, unlayered design-mode rules already outrank Tailwind's layered utilities. Add stable role hooks only on actual material-bearing surfaces/controls. For a demonstrated conflict with another unlayered rule, inspect source order and specificity for that exact selector, then fix only that role or exclude its intentional exception. Do not make global `button`, `div`, `section`, `table`, or all-card overrides. Keep mode declarations limited to visual properties; preserve data state, focus, disabled, error, loading, status, keyboard behavior, and content.

## Deliberate preservation and priority order

1. **Use the correct layer model.** Package Tailwind utilities are layered, while design-modes.css is imported unlayered. Unlayered normal rules win over layered normal rules regardless of specificity; do not broadly increase specificity to address Tailwind. The generic button material rule must be checked against ButtonGroup because it can override the group's intended joined-corner utilities.
2. **Resolve only demonstrated unlayered conflicts.** In docs, `apps/docs/src/styles.css:160` `.preview-stage > *` applies padding, border, radius, background, filter, and shadow to every direct preview child. Docs styles are unlayered and imported after design-modes.css (`main.tsx:20–21`), so this rule can override material treatment on the previewed component root. It is docs fixture chrome, not a package component rule; scope it to an explicit preview-frame role if it should not affect previewed roots, or treat it as intentional.
3. **Add hooks to actual material-bearing roots/parts.** The inventory identifies exact roles. A broad selector for every `rounded-sm` element would alter indicators, tags, chart marks, nested utility layouts, and data viewers.
4. **Keep semantic shapes and state.** Full-round avatars, radios, switch/slider mechanics, chips, floating dock, joined button group seams, fullscreen Dialog, underlined fields/tabs, status badges, selected/current rows, and severity colors are intentional. Any selector must leave these state/data affordances legible.
5. **Do not use blanket padding/margin fixes.** `--space-*` tokens already appear widely; `gap-1/2/3`, `p-1`, and a few `mt-6` are utility spacing, but most are local hierarchy (menu item insets, dialog footer, list indent). Design modes currently have recipe spacing only for app/workspace dashboard compositions. Change spacing only for measured overnesting with a root/part hook, not every nested box. Prioritize actual double borders/surfaces: QueryBuilder groups, menu/popover nesting, prompt shell around textarea, and node editor chrome.
