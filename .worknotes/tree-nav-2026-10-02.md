# TreeNav 편입 작업

## 선택과 동작

기존 `Tree`는 파일·리소스의 선택 상태를 다루고 `Sidebar`는
한 단계의 페이지 링크를 제공합니다. 여러 단계의 앱 경로를
접고 펼치면서 실제 링크를 유지하는 용례가 남아 있어 handoff의
`TreeNav`를 독립 component로 선택했습니다. W3C WAI-ARIA APG의
disclosure navigation 의미 구조를 참고했고 코드는 복사하지
않았습니다. 새 npm 의존성은 없습니다.

호출자는 현재 페이지와 실제 라우팅을 소유합니다. component는
현재 링크의 `aria-current="page"`, 조상 경로의 초기 펼침,
경로 변경 시 새 가지 펼침을 담당합니다. 부모 링크와 하위 목록
버튼은 별도 조작입니다. 그룹에 href가 없으면 버튼 자체가
목록을 펼칩니다. 확장 상태는 기본적으로 내부에서 관리하고,
`expandedIds`를 주면 호출자가 관리합니다. `rail`·`filled`는
공통 token을 사용하는 표시 형태입니다.

## 확인한 범위

로컬 targeted 테스트 3/3은 중첩 링크와 현재 페이지,
잘못된 ID·URL·상태, 펼침과 경로 변경을 확인했습니다.
`npm run typecheck`와 UI 테스트 169/169가 통과했습니다.
로컬 Chromium에서
disclosure 버튼의 Enter·Space, focus 유지, 현재 경로 변경,
링크 클릭과 현재 페이지 표시를 확인했습니다. 첫 preview의
좁은 상세 패널을 세로 배치로 조정했고, 390px dark에서
가로 넘침과 page error가 없었습니다.

build·registry 검사, snapshot, PR·배포·공개 URL은 아직 확인하지
않았습니다. 따라서 공개 119개 component·
121개 item·40개 snapshot과 goal 관리용 추정 약 94%는
유지합니다. 실제 보조기술 발표는 확인하지 않았습니다.
