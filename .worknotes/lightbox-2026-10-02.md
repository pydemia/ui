# Lightbox 편입 작업

## 선택과 구현

`Image`는 단일 이미지, `Carousel`은 페이지 안의 슬라이드,
`Dialog`는 일반 modal입니다. 사진 갤러리에서 확대·탐색·focus
복귀를 매번 조합해야 하므로 handoff의 File & media 후보인
`Lightbox`를 독립 component로 선택했습니다. 외부 component
source를 복사하지 않고 기존 Button·Dialog·Image와 token을
조합했습니다. 새 npm 의존성은 없습니다.

호출자가 목록과 선택·열림 상태를 소유합니다. 제목, alt,
caption, 위치, 이전·다음 버튼, 썸네일과 `frame`·`immersive`
표시를 제공합니다. 목록의 끝에서는 이동을 막습니다. 열었던
요소를 기억해 Escape나 닫기 후 focus를 복원합니다.

## 검증 상태

- 로컬 Chromium: 첫 그림을 열어 방향키로 1→2→3번째 그림을
  이동했고, 마지막 다음 버튼의 비활성화와 선택 썸네일 상태를
  확인했습니다. Escape로 닫으면 원래 갤러리 버튼에 focus가
  복귀했습니다.
- 390px dark: 전체 화면 modal은 390px, 프레임 modal은 358px
  폭으로 표시됐고 문서의 가로 넘침과 브라우저 오류가 없었습니다.
- 실제 screen reader·touch·Safari·RTL은 검사하지 않았습니다.
  기존 registry 형식의 개별 소비자 설치도 수행하지 않았습니다.

`npm run typecheck`와 전체 UI 테스트 163/163, `npm run build`,
`registry:check`·`registry:release-check`가 통과했습니다. 로컬
118개 component·120개 item의 39번째 snapshot은
`sha256-dea2f171b25188f27f7de81b2fefe2294be42a457bf3aef07fadbb6cf9d3c0bc`입니다.
PR #68의 Verify UI와 병합 commit `3657163`의 Verify UI·Pages가
통과했습니다. Vercel production
`dpl_4B3nXyN7dTSw2cUcZkKHAkAddRbi`는 READY입니다. 공개
사이트와 현재·39번째 snapshot의 manifest·Lightbox item URL은
HTTP 200이고 manifest의 `itemCount`는 120입니다. 공개 118개
component·120개 item·39개 snapshot으로 확인했습니다. 로컬
동작 검사를 공개 사이트에서 다시 조작하지 않았습니다.

goal 관리용 추정은 **약 92% → 약 93%**입니다. 갤러리 탐색과 focus
복귀라는 독립 사용처를 공개했고 공급 경로를 확인한 결과입니다.
이는 component 개수의 비율로 계산한 값이 아닙니다.
