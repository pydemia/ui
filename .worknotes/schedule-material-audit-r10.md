# Schedule material audit R10

Read-only audit of `gantt.tsx`, `calendar.tsx`, `calendar-scheduler.tsx`, `calendar-heatmap.tsx`, `design-modes.css`, and their catalog demos. No product files, build output, Git state, or registry snapshots were changed.

## Findings

- `Gantt` has no `data-ui` or `data-slot` hooks. Its outer region is a rounded bordered `bg-surface` panel (`gantt.tsx:227-230`); the title strip and selected-task summary have only utility classes (`231-271`). These pin the palette but do not consume `--surface-fill`, `--surface-image`, `--surface-filter`, `--panel-border-style`, or `--card-decoration`.
- The horizontal scroll viewport is `gantt.tsx:276-279`. The timeline header is `280-297`; its sticky left header cell is `282-285`. Task rows are `345-381`; the sticky task-name cell is `348-350`, and selection is exposed as `aria-pressed` on its button (`351-362`). These are the key opaque-overlap seams: sticky cells need a material-aware backing and must stay above the scrolling grid while horizontal scrolling.
- The day/week grid is an inline `backgroundImage` on each timeline row (`382-394`), so a CSS `background-image` rule cannot replace it. Task bars carry inline accent-mix background color (`395-409`); progress uses `bg-accent` (`410-417`). A theme adapter should expose grid/bar paint via CSS custom properties and use those properties in inline styles or add an overlay layer. Selection already has a focus ring (`399-400`) and a pressed task button state; preserve those contracts.
- `Calendar` has no `data-ui` hook. Its root is the `DayPicker` element with `bg-surface` (`calendar.tsx:13-20`); month, caption, navigation, weekday, day and selected states are mapped through `classNames` (`20-58`). Selected days are identified through the `selected` modifier class applied to the day wrapper and its button (`50-53`). Existing class names are an available semantic seam; prefer adding stable `ui-calendar-*` classes alongside defaults or a root data attribute, while retaining `classNames` merging and consumer overrides.
- `CalendarScheduler` exposes a labeled `<section>` but no design hook; it is a `bg-surface` panel (`calendar-scheduler.tsx:126-131`). Its calendar and agenda are a two-column grid at `138-176`; the agenda panel is `177-178`, and event rows are buttons or divs at `230-249`. Preserve `selectedDate` controlled/uncontrolled behavior and `onMonthChange` / `onSelect` date synchronization (`91-123`, `151-155`), plus event ordering and callback behavior (`97-104`, `230-249`).
- `CalendarHeatmap` already exposes `data-density` and `data-appearance` on its figure (`calendar-heatmap.tsx:118-127`), but panel material is hard-coded as `bg-surface` (`123-125`). Individual day cells expose `data-date`, `data-value`, and `data-missing` (`192-212`), useful hooks for missing/zero/positive states. Each cell's `backgroundColor` is inline and intensity-coded (`188-191`, `207-212`); the legend swatches are also inline (`222-235`). Preserve these data attributes and intensity values while layering mode-specific texture/border treatment around the colors.

## CSS and mode guidance

- `design-modes.css:1-81` defines the reset materials. Relevant tokens include `--surface-fill`, `--surface-image`, `--surface-filter`, `--panel-border-style`, `--panel-radius-material`, `--card-decoration`, `--title-fill`, `--title-ink`, `--table-heading-fill`, `--control-image`, `--control-decoration`, `--pressed-decoration`, and `--bar-image`.
- Mode values are defined at `85-102` (Glass), `120-159` (Material, Neumorphic, Clay), `170-184` (Retro), `233-274` (Cyber, Terminal, Pixel). Current content adapters end before the scoped component rules (`438-456`); component adaptation belongs in the nearest non-Basic scope beginning at `530` and ending at `747`. Scope is limited to the closest non-Basic `[data-design]` and stops at nested design scopes, which preserves nested Basic and independent nested themes. Leave Basic and PRISM source untouched.
- Panel roots should consume the surface fill/image/filter plus material border/radius/decoration tokens. Use `--title-fill` and `--title-ink` in an actual title/header strip, rather than `--surface-subtle`, so modes such as Retro and Swiss keep their intended title contrast. Agenda/event cards can use `--field-decoration` or `--secondary-decoration` sparingly; avoid turning every day cell into a raised card.
- Glass: translucent fill, surface image, blur, and restrained edge highlight on panel/header; sticky Gantt cells require the same material background and backdrop filter so the grid does not show through illegibly. Respect the existing no-backdrop-filter fallback at `749-762`.
- Clay: surface image and card decoration for the outer panel, subtle inset material for selected agenda/day/task surfaces, restrained corner radius. Keep grid cells and task bars compact; do not use the global pill-shaped control radius for them.
- Neumorphic: panel relief on larger roots, recessed grid/agenda wells and a pressed treatment on selected day/task. Keep one clear light/dark light source and retain visible focus rings; avoid deep shadows on every individual date.
- Retro: strong title-fill/title-ink header, square or sharply stepped panel and cell borders, clear pressed inset for selection. Terminal: dashed structural borders, data-font where available, subdued scanline/grid texture, and the existing terminal title palette. Pixel: stepped/clipped panel and selected-state edges plus coarse grid accents; ensure clipping never cuts focus outlines or tiny text.
- Across modes, use background color/material layers that maintain text contrast. Do not replace selected state with a left stripe; use surface/ink/weight and preserve the native focus outline. Preserve date numerals, heat intensity encoding, task progress fill, dependency connectors, and sticky z-index ordering.

## Cascade and implementation pitfalls

- Existing utility classes are passed as `className` strings, so a zero-specificity `:where([data-ui=...])` adapter can lose to utility selectors when both declarations share a cascade layer. Keep adapter rules in the existing unlayered presentation sheet/scope and inspect the compiled cascade if utilities are changed.
- CSS cannot override inline `backgroundImage` / `backgroundColor` on the Gantt grid, Gantt task bars, heatmap cells, or heatmap legend. Convert those inline values into custom-property-based expressions or add separate visual layers; adding a more-specific stylesheet selector is insufficient.
- React DayPicker's `classNames` keys are override points. Keep defaults merged with consumer values (`cn(default, consumer)`) and do not replace `classNames` with a closed internal mapping. Preserve `modifiersClassNames` supplied by the scheduler.
- Do not add new visual semantics by broad selectors such as all `button[aria-pressed]`: the current component uses `aria-pressed` for Gantt selection, and global pressed-button rules already exist (`design-modes.css:352-353`). Scope schedule decoration to stable component/slot hooks.

## Catalog coverage and acceptance checks for implementation

The docs catalog has real interaction demos: Gantt scale toggle, task reset, selection, and dependency samples (`apps/docs/src/catalog.tsx:178-204`); Calendar single/range selection (`1505-1517`); Scheduler controlled date, events, and callbacks (`2077-2100`); Heatmap density, panel/plain, empty state, missing-day and intensity samples (`5028-5053`). Validate those demos under Basic, PRISM, Glass, Clay, Neumorphic, Retro, Terminal, and Pixel, including light/dark appearance and narrow-width horizontal scrolling.

Acceptance should verify: sticky Gantt header and task cells remain opaque and aligned while the day grid scrolls; selected task remains visibly selected and focusable, task buttons still invoke callbacks, scale/date labels and progress/dependency marks stay aligned; Calendar month navigation and single/range selection remain keyboard-accessible with selected/today/outside/disabled states readable; Scheduler controlled and uncontrolled selected dates, month changes, event-count labels, empty state, and event callbacks remain correct; Heatmap retains leap-year dates, missing vs zero, intensity ordering, compact/comfortable sizing, horizontal scroll and plain/panel behavior; nested Basic and PRISM render pixel-identically to baseline; reduced motion and forced-colors treatments continue to work.

No build, tests, browser inspection, publication, or registry work was performed, per audit scope.
