# 작업공간 shell 재감사 (2026-10-14)

대상은 58개 목표 중 `prism-workspace`다. 원본 frontend `dev`와 `origin/dev`는 `2eeb26ff10274745f9d86897c2f2828bff002b98`로 일치했다. `ChatLayout`은 사이드바·본문을 배치하고 공지 팝업, 토스트, 확인창, PDF 작업을 호스트에서 관리한다. `ChatConversationSection`은 대화 스크롤과 입력창을 분리하고 `SidePanel`은 본문 옆의 비모달 상세를 맡는다. 독립 shell은 이 배치 목적을 유지하되 원본 `min-width:1440px`로 생기는 좁은 화면 넘침은 개선한다. 배포 소스 SHA와 인증된 전체 제품 흐름은 확인하지 못했다.

좁은 화면에서 숨긴 데스크톱 사이드바와 Drawer 사이드바가 함께 마운트되던 문제를 고쳤다. 닫힌 Drawer에서는 0개, 열린 Drawer에서는 1개만 마운트된다. 폭이 0인 아직 배치되지 않은 shell은 모바일로 오판하지 않도록 했다. 사이드바의 내부 일시 상태는 Drawer를 닫거나 레이아웃 모드를 바꾸면 다시 생성되므로 보존할 상태는 호스트에서 제어하도록 계약에 명시했다. 완전한 독립 설치 예제에는 메뉴 이동 뒤 Drawer 닫기를 연결했다.

로컬 브라우저에서는 20건의 합성 대화를 표시해 메시지 본문만 내부 스크롤하고 입력창이 하단에 남는 것을 확인했다. 1200px shell에서 440px 상세 패널과 고정 공지 팝업을 함께 열어 문서 가로 넘침 0을 확인했다. 실제 320px 뷰포트에서는 shell과 공지 팝업이 각각 288px이고, 320px shell의 열린 상세 패널은 318px 안에 들어왔다. 기존의 320/390/768/1024px 폭, Drawer 확장 시 닫힘·헤더 포커스, 초안 보존·8개 프로필 탭 검증도 유지된다.

shadcn 레지스트리로 독립 소비자에 현재 source를 설치해 59개 TSX 모듈과 CSS의 바이트 일치, 완전 예제 47개 타입 검사, Vite·Pretendard·고지를 확인했다. 별도 설치본의 실제 320px 화면에서 상세 패널을 열고 모바일 메뉴로 이동하면 Drawer가 닫히며 문서 가로 넘침·콘솔 오류가 없었다. 전체 PRISM 테스트 337개와 workspace typecheck가 통과했다. 테스트의 첫 실행은 폭 0인 DOM 환경을 모바일로 판정해 기존 상세 예제 1건이 실패했으며 위 측정 조건을 수정한 뒤 해당 11건과 전체 337건이 통과했다.

`prism-workspace`를 목적·디자인·개선 허용 기준으로 완료 판정해 **28/58개**, 미판정 30개로 기록한다. 인증된 실제 공지 전달·PDF 작업·라우팅·권한과 배포 소스 SHA는 호스트/배포 검증 범위로 남긴다. 최종 site build, workspace typecheck, registry release check, 생성 `docs/`의 검증 JSON 대조와 `git diff --check`가 통과했다. PR/CI/preview 결과는 게시 후 이 기록에 덧붙인다.
