# Terminal 편입 기록

2026-10-02. 공개 기준은 121개 component·123개 registry item·42개
snapshot이며 goal 관리용 추정은 약 96%입니다. 이 로컬 초안에는
Terminal을 더해 122개 component·124개 item이 있습니다.

## 사용처와 책임

개발 도구 화면에서 명령을 입력하고 실행 결과를 읽는 반복 작업입니다.
기존 `LogConsole`은 로그 표시만 하고 `PromptInput`은 대화 메시지
전송에 맞춰져 있어 명령 이력과 순서 있는 출력을 묶지 않습니다.
handoff의 Content & Developer Tools 후보를 실제 API로 편입했습니다.

`Terminal`은 입력 draft와 이력 탐색 위치를 소유합니다. 호출자는
고유 ID가 있는 `command`·`output`·`error`·`notice` 줄과 실제
실행·결과 저장을 소유합니다. Enter는 공백이 아닌 원문을
`onCommand`에 전달합니다. 호출자가 기록에 추가한 명령을 위·아래
방향키로 다시 선택하고, 마지막에서 내려오면 작성 중이던 문구를
복원합니다. `pending`은 추가 제출을 막고 입력을 유지합니다.
`panel`·`flat`은 같은 동작의 표시 형태입니다. 실제 OS 명령 실행이나
권한 판단은 component에 포함하지 않습니다.

원본 React 구현이며 기존 `pyd-button`·`pyd-utils` 외 새 npm
의존성은 없습니다. W3C WAI의 log role 의미 구조를 참고하고
예제 코드는 복사하지 않았습니다. 출력의 `aria-live`는 기본 `off`로
두고 필요한 화면에서 `polite`를 고를 수 있습니다.
[출처 조사](../research/source-inventory.md)와
[동작 규칙](../research/design-contract.md)을 갱신했습니다.

- UI 테스트 174/174 통과. 새 테스트 2건은 의미 구조·잘못된 줄,
  명령 제출·이력·pending 상태를 확인합니다.
- `npm run build` 통과. registry item 124개와 문서 사이트를
  생성했습니다.
- 로컬 Chromium에서 `help` Enter 실행, 출력 추가, 위·아래
  방향키로 명령 호출과 작성 중 draft 복원을 확인했습니다.
- 390px dark에서 `flat` 전환과 가로 넘침 없음(문서 너비 390px)을
  확인했습니다. 브라우저 error는 없었습니다.
