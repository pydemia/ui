# 공급·품질 판정 범위 재검토

2026-10-02 현재 공개 상태는 129개 component, 131개 registry item,
54개 snapshot입니다. Goal 관리용 추정은 약 97%입니다. 이번 검토는
제품·CI·배포 방식을 바꾸지 않으므로 진척도를 올리지 않습니다.

## 판정

현행 기준은 과거 10개 누적 과제를 새 component의 승인 조건으로 쓰지
않고, component별 PR·snapshot·개별 설치도 요구하지 않습니다. 다만
로드맵의 두 문장은 실제보다 엄격하게 읽힙니다. 개발 중의 모든 변경
commit마다 전체 CI 결과가 있어야 하는 것처럼 보이고, focus·pointer·
browser API 변경에는 관련 자동 테스트가 있어도 브라우저 실행을
추가로 요구합니다.

개발 중에는 변경한 경로의 검사로 확인합니다. 공개 후보 commit에서
적용되는 CI를 확인하고, 변경한 핵심 사용 흐름은 관련 자동 테스트
또는 브라우저에서 한 번 실행합니다. 레이아웃 계산이나 브라우저
고유 동작 때문에 자동 테스트가 그 흐름을 증명하지 못하면 해당
브라우저 흐름을 실행합니다. 같은 동작을 로컬과 공개 사이트에서
반복하지 않습니다. 이 해석을
[로드맵](component-roadmap.md#공급과-품질의-판정-단위)에 반영했습니다.

출시 차단은 적용 CI 실패, 확인된 값 손실·제출 오류·keyboard 접근
불가, 필수 고지·설치·공개 경로 실패, 변경한 핵심 흐름의 실행 증거
부재로 한정합니다. 외부 component 코드를 도입할 때 공식 문서·동일
revision의 source·LICENSE·의존성·접근성 검사를 유지합니다. 직접
구현한 component에는 가상의 upstream 검사를 적용하지 않습니다.
실제 보조기술·touch·Safari·RTL과 전체 item 개별 설치는 관련 지원을
주장하거나 해당 경로를 바꿀 때 검사합니다.

## 남은 고정 비용

`verify.yml`은 제품 PR과 `main` push에서 typecheck, 전체 UI 테스트,
build, registry 및 모든 과거 snapshot을 검사합니다. 비렌더링 문서
PR만 경량 경로가 있지만 `main`에서는 전체 검사를 실행합니다.
`registry-release.mjs`는 새 snapshot마다 모든 item을 두 공개 위치에
복제합니다. 54번째 snapshot은 각 위치에 132개 파일을 추가했습니다.
이는 체크 항목의 수가 아니라 CI·저장 방식의 비용입니다. 반복 비용을
더 줄이려면 CI 범위와 snapshot 저장 형식을 별도 설계·회귀 검증해야
합니다. 기존 고정 URL과 고지 전달을 확인하기 전에는 저장 형식을
바꾸지 않습니다.
