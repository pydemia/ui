# 공급·품질 체크리스트 적용 수준 재검토

후속 실적용 결과는 [HistogramChart 작업 기록](histogram-chart-2026-10-03.md)에
남겼습니다. 원본 component 하나의 공개 검사에는 변경분 중심 기준을
적용했고, 릴리스의 322개 변경 파일 중 280개가 snapshot 전체 복제였습니다.
검사 하한을 더 낮출 근거보다 생성·저장 비용을 줄일 근거가 큽니다.

2026-10-03. 현행 [로드맵](component-roadmap.md#공급과-품질의-판정-단위)은
변경분만 검사하고, 같은 동작과 CI 결과를 반복하지 않도록 정해 두었습니다.
기본 품질 하한은 낮출 필요가 없습니다. 경직성은 그 하한을 개발 중인
후보와 공개 릴리스에 한꺼번에 적용하거나, 자동 생성량과 배포 대기를
component 품질 미달처럼 기록하는 데 있습니다.

이번부터 판정은 다음 세 상태로 기록합니다.

| 상태 | 필요한 증거 |
| --- | --- |
| 구현 검토 | 실제 사용처·기존 API와의 차이, 변경한 동작의 관련 테스트 또는 preview |
| 공개 준비 | export·registry·출처·Usage·preview의 일치, 공개 후보의 적용 CI, 변경한 핵심 동작의 실행 |
| 공개 확인 | 배포 성공, manifest와 변경한 공급 경로의 대표 URL 접근 |

정적 표시에는 실제 preview와 값·경계의 관련 테스트를 사용합니다.
새 focus·pointer·browser API·반응형 동작에는 그 경로를 검증하는
테스트나 브라우저 실행을 추가합니다. 새 설치 형식·target·의존
경로가 없으면 별도 소비자 설치를 반복하지 않습니다. 직접 작성한
component에 일반 개념만 참고했다면 외부 코드의 revision·LICENSE
조사를 요구하지 않습니다. 외부 코드를 편입했을 때는 기존 출처
기준을 그대로 적용합니다.

공개 준비 상태에서 확인된 값 손실·제출 오류·keyboard 접근 불가·
필수 고지 누락·설치 실패·적용 CI 실패는 차단합니다. 핵심 동작의
실행 증거가 없으면 공개 준비로 판정하지 않습니다. Vercel 제한으로
배포되지 않은 후보는 품질 실패가 아니라 공개 대기입니다. 이때
공개 확인을 마친 수량에는 포함하지 않습니다.

사람이 검토할 기록은 작업별 `.worknotes` 하나에 적용한 증거와
확인된 결함, 실제로 적용되지만 실행하지 못한 검사만 남깁니다.
과거 10개 운영 과제의 완료 개수는 릴리스 점수로 사용하지 않습니다.
같은 내용의 검사 결과를 로드맵·진척도·인계 문서에 복제하지 않고,
그 문서에서는 작업 기록으로 연결합니다.

`main`의 비렌더링 문서 변경에 대한 전체 UI 검사 생략은 PR #115와
병합 후 CI에서 확인했습니다. 따라서 이를 남은 고정 비용으로
계속 적지 않습니다. 현재 남은 큰 비용은 provenance 전체 hash가
무관한 item 고지에 전파되고, snapshot 생성기가 매번 전체 item을
`registry/releases/`와 `docs/r/releases/`에 복제하는 구조입니다.
이는 별도 생성·저장 방식 개선 과제이며 이번 component의 품질
체크박스가 아닙니다. 기존 불변 URL·의존 경로·고지 전달을 보존하며
변경해야 합니다.

당시 작업 중이던 `BoxPlotChart`에는 원본 코드의 수치 경계 테스트,
표의 정확한 값, preview와 좁은 화면 배치, 적용 CI를 확인합니다.
외부 코드 편입이나 새 설치 방식의 검사는 적용하지 않습니다.
이번 재검토는 기준 문서와 작업 판정만 바꾸며, 공개 공급이나 goal
관리용 추정 약 98%를 올리지 않습니다.
