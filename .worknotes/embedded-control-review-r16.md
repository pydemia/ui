## Findings

### P2 — Inline NativeSelect reset also suppresses an explicit filled appearance

`packages/ui/src/design-modes.css:1167-1179` applies the chrome reset to every inline native select except `data-appearance="underline"`. It has attribute specificity from `:not([data-appearance="underline"])`, which ties the filled-field rule at `:963-964`; because the inline rule is later, its `background: transparent` wins. Thus an element intentionally marked both `data-presentation="inline"` and `data-appearance="filled"` loses its filled appearance. The only current source call is BlockEditor at `block-editor.tsx:289-307`, and it explicitly uses `outline`, so this is not a defect in that current rendered call. The CSS contract is broader than the callsite and conflicts with preserving explicitly filled variants. Candidate: match `data-appearance="outline"` for this reset, or add a later filled exception that restores `--field-filled-fill` while leaving the inline geometry quiet.

### P2 — BlockEditor disabled select loses an authored disabled visual cue

The same reset removes the field background/border but leaves the callsite's `text-foreground` class in place. BlockEditor passes `disabled={disabled}` (`block-editor.tsx:289`) but its raw select classes (`:297-301`) do not define `disabled:opacity-*` or a disabled cursor. The new inline mode clears the UA-like field surface while the authored foreground remains normal-strength; unlike adjacent Buttons, the select receives no explicit disabled appearance from the shared rule. Native disabled activation/keyboard semantics remain intact, but its disabled state is less visible than the nearby actions. Candidate: add a narrowly scoped `:disabled` opacity/cursor treatment to the inline selector, or add equivalent classes at this callsite. Do not apply opacity to enabled or selected state.

## Checks with no defect found in current source

- **Basic isolation:** the new inline NativeSelect and table action rules are inside the non-Basic `@scope` at `design-modes.css:1166`; `to ([data-design])` limits the scope at nested design roots. Basic controls therefore do not receive these resets. The docs preview frame rule in `apps/docs/src/styles.css:180-200` changes only the example wrapper surface.
- **Inline native selection:** current BlockEditor uses a raw native `<select>`, not the `NativeSelect` wrapper with its extra ChevronDown. `appearance: auto` at CSS `:1168` therefore preserves the browser’s native picker affordance; the React `value`/`onChange`, options, accessible label and disabled attribute remain present (`block-editor.tsx:289-307`). The focus-visible outline is explicit at CSS `:1181`. This finding assumes the current raw-select call; applying the internal marker to `NativeSelect` itself could show both the native arrow and the wrapper Chevron and should be avoided.
- **Embedded action cascade:** `[data-slot="surface-action"]` at CSS `:882-894` is later than Button’s outline decoration and clears border, background, shadow and clip-path while preserving Button’s control height, disabled opacity/pointer behavior and focus ring. Current BlockEditor, Carousel, Lightbox and NodeCanvas action slots are only attached to secondary/utility actions; disabled previous/next/zoom actions keep their disabled attributes. Selected `aria-pressed` surface actions receive the embedded selected fill. The global broad `button[aria-pressed]` paint at CSS `:389-390` remains, but the new `surface-action[aria-pressed="true"]` rule at `:892` wins for controls marked with this slot. NodeCanvas node selection is still a distinct node-title control with its own outer selected ring/border, not a new failure introduced by the inline-control selectors.
- **DataTable controls:** the row disclosure keeps `aria-expanded`/conditional `aria-controls` and a 32px target; table sort receives a 32px minimum height and a focus-visible outline (`design-modes.css:1182-1192`, `data-table.tsx:374-398,443-461`). The preview’s `DataTablePreview` is wrapped in `.preview-workspace` (`catalog.tsx:4357`), which is directly covered by the wrapper reset (`styles.css:180-200`), so its table frame is not double-framed by the docs preview shell.
- **Carousel state:** current slide is still exposed through `aria-current` and `aria-disabled`; the visible indicator is a separate accent/border dot (`carousel.tsx:204-233`). The surface-action changes affect only previous/next buttons, not the selected indicator.
- **Danger/current semantics:** the reviewed new rules do not target danger classes/text, `aria-current`, or the lightbox thumbnail current state. They preserve explicit mode-selected Navigation/Tree surfaces outside these files; no changed selector here erases a danger treatment or current-state marker.
- **No runtime claims:** these conclusions follow from source order and current JSX. Browser computed style, disabled native rendering across platforms, and keyboard focus appearance remain unverified.
