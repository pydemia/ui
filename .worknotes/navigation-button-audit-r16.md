# Embedded-control and navigation button audit R16

- Scope: all 28 entries in `.worknotes/browser-evidence/geometry-r14/inventory.json` whose family is Framework, Navigation, Workflow, Layout, or Content. Read the component source under `packages/ui/src/components/`, relevant design-mode rules in `packages/ui/src/design-modes.css`, and docs/catalog callers in `apps/docs/src/catalog.tsx` and workspace files. Read-only source audit; no product changes, browser runs, builds, or tests.
- User-provided screenshot observations carried into this audit: Glass Tree disclosure glyphs appear as tiny white disks; TreeNav has a large detached arrow/end button and its parent row reads as filled; NavigationMenu active link becomes a white pill; AnchorNav example content is clipped at the bottom. These are reported observations, not independently reproduced in this pass.
- Out-of-inventory screenshot references: `Accordion` and `NativeSelect` are not among the 28 IDs. Their source is still relevant to root follow-up: `accordion.tsx` exposes `data-ui="accordion-trigger"` and R15 CSS adds a field-radius/14x12 trigger plus hover/open relief at `design-modes.css:917-920`; `native-select.tsx` exposes `data-ui="native-select"`, shared sizing starts at `design-modes.css:937-939`, and callers include `data-table.tsx`, `log-viewer.tsx`, `query-builder.tsx`, and `catalog.tsx`. Treat the oversized native-select field as a control-family finding, not a 29th inventory row.

## Cross-cutting findings

1. `design-modes.css:682-709` already centralizes the right semantic hooks: `tree-row`, `tree-nav-link`, `tree-nav-disclosure`, `nav-link`, `anchor-nav-link`, `nav-menu-link`, and `nav-trigger`, with separate hover, current/selected, and focus-visible states. This is the best integration point for theme-aware quiet controls.
2. Cascade correction: `apps/docs/src/styles.css` imports `tailwindcss` (its utilities are layered) and the app imports `@pydemia/ui/design-modes.css` as ordinary CSS, outside `@layer`; R15 runtime evidence confirms the mode rules apply. Normal unlayered rules beat normal layered utilities regardless of specificity, so the shared mode rules, not component utilities, own the reported fill and decoration. `:where(...)` still matters when two normal unlayered rules compete, or when an unlayered override is added: it gives specificity zero. For example, the same-layer NativeSelect rule at `design-modes.css:394` adds `:not([data-appearance="underline"])` specificity (0,1), so a future inline NativeSelect override must account for that. Avoid broad selectors and `!important`.
3. The same unlayered central block explicitly assigns `field-radius`, `navigation-hover-fill`, and `field-decoration` to both tree disclosure slots (`design-modes.css:710-716`). In Glass, `--navigation-hover-fill` is a surface mix (`:571-574`) and field decoration includes mode-specific highlights; that combined shared styling explains the reported white disks. The Tree's disclosure is an `aria-hidden` 16px span whose click bubbles into the treeitem handler, not an independent button; retain the whole-row treeitem target and keyboard model while removing the detached paint.
4. Keep quiet/transparent as the resting treatment for embedded navigation, inline actions, disclosures, and toolbar controls. Preserve intentional surfaces for panel/column/card containers, primary submit/create actions, explicit selected states, selection widgets, and user-requested filled variants. For stateful navigation, retain `aria-current`, `aria-selected`, `aria-pressed`, `aria-expanded`, visible focus, disabled state, and keyboard behavior. The 21 mode character comes from its tokens and should remain in selected/focus/hover accents and component shells, not be flattened by a universal transparent-button rule.

## Prioritized exact hooks for root integration

1. **P0: shared navigation/tree resting paint.** Adjust the owning unlayered declarations in `design-modes.css:682-709` for `tree-row`, `tree-nav-link`, `tree-nav-disclosure`, `nav-link`, `anchor-nav-link`, `nav-menu-link`, and `nav-trigger`. They outrank layered Tailwind utilities regardless of `:where` specificity. Remove default fill/decoration only; leave explicit state selectors for hover, `aria-current`/`aria-selected`/`data-active`, and `:focus-visible`. Preserve accent-filled `tree-nav[data-variant=filled]`, bottom dock, underline, and intentional user-selected variant.
2. **P0: Tree and TreeNav disclosure disks.** For Tree, `data-slot=tree-disclosure` is decorative/click target inside the keyboard-managed tree row. For linked TreeNav parents, the second `button[data-slot=tree-nav-disclosure]` is a separate accessible action with `aria-expanded` and `aria-controls`, so preserve its target and independent focus; remove its resting field decoration and center a small glyph in the shared row.
3. **P1: navigation menu active pill.** Adjust the unlayered `nav-menu-link[data-active]` state rule at `design-modes.css:700-706` and trigger open/hover rule at `:696-699`. Keep active route and open-menu state perceptible; theme-selected/hover tokens can supply mode character without a permanent white capsule.
4. **P1: in-surface actions.** Apply quiet-default styling to action slots: `surface-action` in Kanban/app-shell, `gantt-action`, BlockEditor toolbar controls, sidebar collapse, carousel previous/next, resizable handle, and schedule event rows. Do not capture submit/create/launch actions or field controls under generic selectors.
5. **P1: AnchorNav clipping diagnosis.** The component rail has no explicit max-height or overflow clip. Trace `AnchorNavPreview` and its docs preview ancestors in `apps/docs/src/catalog.tsx` around lines 7887-7895 and the shared preview frame before proposing source geometry changes. The horizontal variant intentionally scrolls.
6. **P2: explicit selection boundaries.** Keep `aria-current`, `aria-selected`, `aria-pressed`, Radix `data-state=active`, current step, and `aria-expanded` visuals in Tabs, MasterDetail, Tree, TreeNav, Sidebar/Navigation, Gantt, NodeCanvas, Carousel, Board, and Stepper. Test that transparent rest styles do not erase those states, disabled treatment, or focus rings.
