# Verify UI의 문서 PR 검사 범위

2026-10-02. goal 관리용 추정은 약 97%입니다. 공개 공급물은
126개 component·128개 registry item·51개 snapshot입니다.

변경 전 `Verify UI`는 모든 PR과 `main` push에서 UI 테스트·build·
registry 검사를 실행했습니다. 문서 조사 기록만 고쳐도 같은 비용이
들었습니다. workflow의 PR 경로 검사를 추가해 `.worknotes/**/*.md`,
`research/**/*.md`, 루트 `README.md`·`CHANGELOG.md`·`NEXT_SESSION.md`만
바뀐 PR은 diff 공백 검사만 실행하도록 했습니다. 문서 링크와 문구는
검토자가 변경 내용을 확인합니다. 앱 문서인 `apps/docs/`, 생성된
`docs/`, component·registry·스크립트·설정·workflow 변경은 기존
전체 검사로 보냅니다. `main` push도 기존 전체 검사를 유지합니다.

같은 `verify` job을 유지하므로 required check의 이름은 변하지
않습니다. PR의 base commit과 checkout된 merge commit을 비교하며,
변경 파일이 없거나 허용 목록 밖 파일이 하나라도 있으면 전체 검사를
실행합니다. 문서 PR에서도 `git diff --check`는 실행합니다.

로컬에서 workflow YAML을 파싱하고 diff 공백 검사를 통과했습니다.
실제 workflow의 scope shell은 기록 전용 diff에서 `full=false`,
workflow 변경 diff에서 `full=true`를 반환했습니다. snapshot 저장
방식은 바꾸지 않았습니다.

PR #94의 Verify UI run `36999794077`은 전체 검사 경로에서
typecheck·UI 테스트·build·registry 검사를 통과했습니다. 병합 commit은
`75db3454a6488cac6b1ce95b5404646d214cf7f7`입니다. 이 commit의
`main` Verify UI run `37000078382`와 Pages run `37000077520`도
성공했습니다.

기록 파일 두 개만 바꾼 PR #95의 Verify UI run `37000226281`은
diff 공백 검사가 성공하고 npm 설치·typecheck·UI 테스트·build·
registry 검사가 `skipped`인 것을 확인했습니다. 병합 commit
`c858cdf17722f2fc63ebbb811b11c3a94f08c3da`의 `main` Verify UI
run `37000377518`과 Pages run `37000376778`도 성공했습니다.
비렌더링 Markdown PR의 경량 경로와 `main`의 전체 경로를 모두
실행으로 확인했습니다.
