# 공급·품질 기준 후속 재검토

이 문서는 당시의 판정 기록입니다. 현재 적용 기준은
[반복 검사 축소](quality-criteria-simplification-2026-10-02.md)와
[로드맵의 판정 단위](component-roadmap.md#공급과-품질의-판정-단위)를
참고하세요.

2026-10-01. [앞선 재검토](quality-criteria-review-2026-10-01.md)와
[로드맵](component-roadmap.md)의 판정 문구를 다시 읽었습니다. 코드를
실행하거나 새 환경에서 품질을 검증한 작업은 아닙니다.

## 관찰

기존 10개 체크박스는 완료 5·부분 4·미검증 1입니다. 이 수치는
106개 component의 공급률이 아닙니다. 일부 항목은 완료 조건의 범위가
계속 늘어납니다. 예를 들어 export·registry 자동 대응 검사가 통과해도
과거 Usage 전체의 수동 재검토가 끝나지 않으면 1번은 부분으로 남습니다.
3번은 drag·touch·시간대·보조기술을 한 항목에 묶고, 5번은 현재 릴리스
절차와 과거 provenance를 함께 묶습니다. 6번의 장기 URL 보존은 시간이
지나야 관찰할 수 있으므로 매번 완전 종료를 기대하기 어렵습니다.

앞선 재검토는 새 component의 공개 snapshot을 별도 소비자에 설치하도록
적었습니다. 모든 component를 하나씩 배포하고 소비자 프로젝트를
새로 만드는 방식은 릴리스 단위의 의존성 검사를 중복합니다.
`quality-criteria-review-2026-10-01.md`에는 같은 릴리스의 여러 item을
하나의 소비자 검사로 묶을 수 있다고 적혀 있어 문서 사이 판정도
달랐습니다.

## 변경한 판정

- component의 독립 사용처, 값·상태·focus 동작, 참고한 upstream의
  공식 문서·고정 소스·LICENSE·의존성, 출처 구분은 유지합니다.
- package export·registry·provenance·token·문서 Usage의 변경분을
  대조하고 typecheck·관련 테스트·build·registry 검사를 실행합니다.
  새 상호작용은 영향받는 브라우저 흐름을 확인합니다. 문서만 바뀐
  경우에는 해당 링크·예시·preview와 문서 build를 확인합니다.
- 새 소비자 설치는 **릴리스 단위**입니다. 변경 item과 그 의존 item을
  한 소비자에 함께 설치해 typecheck·build합니다. 새로운 의존성
  체인이나 설치 target이 다를 때만 별도 설치를 추가합니다. 공개
  배포 후에는 실제 snapshot URL로 같은 공급 경로를 확인해야
  `공개 공급 확인`으로 기록합니다. 각 item의 개별 설치를 모두
  검사했다고 쓰지 않습니다.
- 값 손실, 제출 오류, 키보드 진입·탈출 불가, 필요한 고지 누락,
  설치·build 실패처럼 확인된 주요 결함은 수정판 검증 전까지
  ready-made 완료로 표시하지 않습니다. 관찰하지 않은 환경은
  통과가 아닌 미검증으로 적습니다.
- 오래된 component의 전수 재검사, 실제 screen reader·touch·Safari·
  RTL 표본, 모든 item의 단독 설치, rollback 뒤 snapshot URL 보존은
  라이브러리 전체의 품질 과제로 둡니다. 해당 지원을 명시적으로
  주장하거나 변경이 그 경로에 영향을 줄 때는 관련 검사를 앞당깁니다.

따라서 진행 보고에서 `5/10`을 공급·품질 점수처럼 반복하지 않습니다.
완료 5·부분 4·미검증 1과 남은 구체적 위험을 기록합니다. 특히
Vercel 과거 배포로 rollback할 때 최신 snapshot URL이 사라질 수 있는
문제는 해결되지 않았습니다. 릴리스 품질과 별개로 운영상 우선 과제로
유지하며 장기 주소 보존을 이미 보장한다고 주장하지 않습니다.

이번 검토는 구현·릴리스·새 검증을 추가하지 않았습니다. goal의
관리용 추정은 약 81%로 유지합니다. 106개 component·108개 registry
item·25개 snapshot은 직전 YearPicker 공개 검증 기록 기준입니다.
