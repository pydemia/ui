# R11 source and catalog audit: Framework, Layout, Data display, Data & analytics

## Scope and evidence

- Read-only audit of the 35 matching inventory entries: Framework (5), Layout (2), Data display (8), Data & analytics (20). Source reviewed under `packages/ui/src/components/`; material adapter reviewed in `packages/ui/src/design-modes.css` (R9 tokens plus R10 navigation/schedule adapters).
- Opened the local component catalog at `http://127.0.0.1:5218/` and visited each of the 35 matching live previews in Clay Light. The catalog announced the selected component and exposed each demo's rendered content/controls; the entries below record the visible preview. This is a source/preview audit, not a 39-mode or pixel-contrast verification.
- Labels: **already-adapts** means existing mode token hooks cover the meaningful surface or there is no material surface to adapt; **needs-material-seam** means a visible shell or interior surface has fixed treatment and lacks the mode's appropriate surface shape/boundary/relief; **intentional semantic/data/media paint retained** means visible paint communicates content or media and should remain as-is.
- `data-ui` absence alone is not a defect. Recommendations use existing variant/appearance hooks where possible and add a stable slot only if a shared CSS hook otherwise cannot identify a genuinely painted surface.

## Ranked actionable hooks

1. **P1 — Shared material contract for genuinely framed surfaces.** Extend the current token vocabulary with data/panel surface tokens (or consistently reuse `--panel-radius-material`, `--panel-border-style`, `--surface-fill`, `--surface-image`, `--surface-filter`, `--card-decoration`, `--panel-shadow`) and target existing `data-appearance="panel"` / `data-variant="panel"` roots. Make Glass supply translucent fill + blur/image; Clay supply its raised surface image/shadow; Neumorphic supply inset/rest relief; Retro and Terminal supply their hard/dashed edge and solid surface. The current `--data-fill` only changes `background-color` for `table, figure, [role=log]`; it does not provide a boundary, radius, relief, backdrop or per-mode fill for all styles. Its default is `initial`, so the generic rule also clears a figure's utility background in modes that do not override `--data-fill`.
2. **P1 — Framework/layout shell surfaces.** Extend app-shell recipe tokens to framed shell, inset sidebar/main, help bubble and its popover. Add narrowly scoped root hooks to MasterDetail, ResizablePanels, Sidebar and ItemList panel. Apply to their shell, heading/divider, selected row and handle as separate slots. Do not style ScrollArea's host surface or R10 SideNav selected row through a broad descendant rule.
3. **P1 — Chart frame versus plot canvas.** Add a shared chart-panel adapter keyed by real panel appearance/variant. Where roots need an identifiable hook, add `data-ui`/`data-slot` to chart panel roots or inner plot canvas in source, then use CSS selectors; this hook is justified by actual fixed paint. Keep the outer frame separate from the inner plot canvas. Use existing CSS grid/axis/stroke/data classes for axes, legends and marks. This covers BarList, BulletChart, FunnelChart, WaterfallChart, BoxPlotChart, HistogramChart, TreemapChart, RadarChart, SankeyChart, PivotTable, DataChart, DonutChart, Heatmap and ScatterChart. CalendarHeatmap already has its R10 frame adapter.
4. **P2 — Nested surfaces and subtle Card.** Adapt Card `subtle`, QueryBuilder `query-condition` and panel `query-group`, Treemap canvas, and any chart tooltip to lower-emphasis material tokens; retain semantic hierarchy so nested panels do not all receive the same elevated shadow. ItemList panel heading may use `--title-fill` / `--title-ink` with a clipped parent radius.
5. **P2 — Keep data contracts explicit.** CSS changes may change only surfaces around data: retain series colors; success/warning/danger status colors; all data-to-size/position mappings; SVG axes, marks, target/reference lines; missing-data dashes/labels; exact-value tables; selected/focus state and keyboard behavior. Do not blanket-style every `figure`, `table`, `td`, or `svg`, and do not turn a data encoding into a design-mode accent.
