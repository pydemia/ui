Scope: read-only audit of `packages/ui/src/components`, `packages/ui/src/design-modes.css`, `apps/docs/src/styles.css`, and `apps/profile-demo/src/app.css`. No product source was changed. ## Existing token and scope behavior

This is the most centralized place to attach a design-level curvature token; component rules below consume those radius variables.
- Design tokens are also supplied as inline style tokens by `resolveThemeTokens()` in `packages/ui/src/components/foundation/design-mode-settings.ts:149-163`. Radius values come from profile definitions in `packages/ui/src/components/foundation/design-modes.ts`.
- Largest rounded profiles found: Glass `16px/22px` radius/panel at `design-modes.ts:317-320`; Material `12px/24px` at `349-352`; Neumorphic `16px/22px` at `414-419`; Bento `16px/24px` at `481-485`; Clay `28px/34px` at `520-525`; Spatial `20px/28px` at `896` (see the profile entry); Aurora is `18px/24px` at `713-716`. Clay's CSS further sets `--field-radius:18px` at `design-modes.css:560`.
- Additional direct geometry overrides are at `design-modes.css:151-156` (Material `--control-radius:999px`, asymmetric field corners), `174-181` (Clay `--control-radius:999px`), `560` (Clay field), and `590` (Material schedule bar `999px`). Bento's navigation radius is `12px` at `635`.
- Component radii in `design-modes.css` are normally semantic token applications (`672`, `685`, `714`, `727`, `796`, `802-803`, `843`, `852`, `860`, `885`, `901`, `906-916`, `923-934`, `986`, `1044-1057`, `1065`, `1111-1119`, `1126`, `1135-1142`, `1177-1187`). A global curvature treatment should preserve each existing finite `border-radius` geometry while changing corner treatment; do not globally replace radius values with a single radius.

- Avatar root has no `data-ui`/`data-slot` hook: it uses `relative flex size-9 shrink-0 overflow-hidden rounded-full` in `packages/ui/src/components/avatar.tsx:9`. Target the component-owned class/API or add a stable hook if needed; do not rely on an invented `[data-ui="avatar"]` selector. Avatar group overlap badge uses `rounded-full` at `avatar-group.tsx:104`; retain its round contour.

## Scope / cascade cautions for the implementation

- `@scope ([data-design]:not([data-design="basic"])) to ([data-design])` in `design-modes.css:669` is already used to keep component styling from crossing a nested design boundary; `apps/docs/src/styles.css:395` uses the same boundary pattern. Put any descendant-wide squircle reset within a bounded non-Basic design scope (or equivalent explicit nested-theme exclusion), so an inner `[data-design="basic"]` fully retains its current geometry. Basic is also explicitly reset in `design-modes.css:109-113`.
- A portal is outside its logical ThemeScope in the DOM unless it carries its own `data-design`; component styles scoped to the trigger's ancestor won't automatically reach portal content. Portal roots need their effective design marker/token scope before expecting broad corner styling to apply.
- Existing `border-radius: inherit` and logical-corner inherit rules are deliberate clipping/composition contracts: `design-modes.css:872-873`, `908-913`, `1017-1034`, `1150-1154`. Squircle selection must follow the same geometry through nested headers, logs, media placeholders, field addons, and button-group edges; otherwise child clipping may appear square or visually detached.
- Curvature can reveal clipping/shadow seams. Overflow clipping is explicit on avatar image (`avatar.tsx:9`) and on full progress/slider rails; rounded parent + child fill may need matching finite radius. Surface shadows are separate from clipping and should keep the parent silhouette aligned (e.g. `design-modes.css:672-676`, `906-912`).
- CSS has direct radius declarations outside tokens: docs clay selectors at `styles.css:257-263,275-282`; docs `.intro-count` circle at `:372`; docs custom per design rules and simple hard-coded 3-5px developer chrome around `:44,75,112,122,129,145`. Avoid changing the docs' independent chrome globally unless explicitly included; bounded design scopes should touch content surfaces while preserving Basic.
- `PRISM` content uses its own `data-prism` surface and source CSS; this audit found no profile-demo CSS radius rules. Keep the global reset scoped to actual `[data-design]` content and do not style arbitrary descendants in PRISM's separate subtree.

## Handoff summary

Useful hook inventory for protected circle exceptions: `[data-ui="avatar"]`, avatar group overlap marker, `[data-ui="switch"]` track/thumb class hooks, radio default outer+dot (leave radio card alone), slider thumb (leave rail finite), skeleton `[shape="circle"]` (leave `[shape="line"]` finite), carousel dots, donut point, timeline marker, app-shell/conversation markers as confirmed circular. Progress bars, chart rails, filter/navigation pills, and docs Clay tags are finite-radius candidates. R19 joined rows remain radius 0. Basic and PRISM preserve current shape.
