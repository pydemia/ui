# 공급·품질 체크리스트 부담 재검토

2026-10-02. 공개 기준 113개 component·115개 registry item·32개
snapshot, goal 관리용 추정 약 88%입니다. 이 기록은 기존 기준과 CI의
적용 비용을 검토한 결과입니다. 제품 코드·검사 설정·출시 판정은
바꾸지 않았습니다.

## 확인한 과잉 부담

- 현재 로드맵은 위험별 검사 표를 앞에 두지만, 바로 아래에 2026-09-29의
  10개 체크박스를 그대로 보여 줍니다. 조사 범위와 종료 시점이 서로 다른
  항목이어서 `5/10`을 현재 공급률이나 승인 점수로 읽으면 안 됩니다.
- `Verify UI`는 모든 PR에서 `registry:release-check`를 실행합니다.
  registry 내용이 바뀌면 현재 빌드와 일치하는 내용 해시 snapshot이
  PR에 있어야 합니다. PR #56에서는 월 탐색 배치와 예시 상태 표시를
  고친 commit 하나에 snapshot 복사본을 포함해 245개 파일이 바뀌고
  5,688줄이 추가됐습니다. 공개되지 않은 이전 draft snapshot까지
  릴리스처럼 보존할 필요가 있는지는 재검토해야 합니다.
- `registry/provenance.json`의 키보드 검증 문구 한 줄을 실제 결과로
  갱신해도 소비자 고지의 provenance SHA-256·commit을 다시 고정하고
  전체 item snapshot을 재생성해야 합니다. 출처·LICENSE의 고정 정보와
  시간이 지나며 바뀌는 검증 상태가 한 파일에 묶인 영향입니다.
- 같은 변경의 로컬 테스트·PR CI·공개 사이트 동작 재실행, 표준 item별
  소비자 CLI 설치는 이미 현행 기준에서 기본 의무가 아닙니다. 이를
  10개 누적 체크박스와 함께 읽으면 여전히 필수처럼 보입니다.

## 권장 판정

현재 구현을 `ready-made`로 공급할 때는 적용되는 CI, 변경한 핵심
상호작용의 실행 증거, 설치 가능한 export·registry·Usage, 필요한
출처·LICENSE 고지와 배포 URL을 확인합니다. 확인된 값 손실·제출 오류·
키보드 접근 불가·설치 실패와 필수 고지 누락은 수정판 검증 전까지
차단합니다. 실제 browser API·pointer 좌표·focus 이동·핵심 반응형
배치가 새로워졌을 때만 해당 브라우저 흐름을 실행합니다.

새 설치 형식·target·의존 경로에는 별도 소비자 설치를 적용합니다.
외부 코드를 도입할 때는 공식 문서, 동일 revision 소스·LICENSE와
의존성을 대조합니다. 영향을 받는 화면 폭·theme만 시각 검사합니다.
screen reader·touch·Safari·RTL 표본, 과거 component 전수 검사,
모든 item의 개별 설치와 rollback 뒤 URL 보존은 범위와 담당 작업을
적어 추적하되 일반 component 출시의 공통 차단 조건으로 두지 않습니다.
해당 환경 지원을 주장하거나 그 경로를 변경할 때는 검사를 앞당깁니다.

운영 문서에서는 현재 적용 기준을 한 곳에 두고, 과거 10개 체크박스는
날짜가 붙은 조사 기록으로 옮기는 편이 명확합니다. snapshot은
**공개할 릴리스 묶음당 하나**가 적절합니다. 공개 전 draft의 중간
snapshot을 보존해야 한다는 현재 규칙은 없습니다. 이 변경에는 CI의
`registry:release-check` 적용 시점과 미공개 snapshot 정리 절차를
함께 조정해야 하므로 이번 검토만으로 규칙을 바꾸지 않았습니다.
provenance의 출처·LICENSE 고정값과 검증 실행 결과를 분리하면
검증 기록만 바뀔 때 116개 item snapshot을 새로 만들 필요가
없습니다. 소비자 고지가 참조하는 출처 기록의 정확성은 유지해야 합니다.

코드·배포 검사는 새로 실행하지 않았습니다. 기준 해석만으로 goal
추정이나 공개 component 수를 올리지 않습니다.
