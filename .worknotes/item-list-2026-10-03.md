# ItemList 공급 작업

2026-10-03 착수. `Spinner`는 이미 다섯 형태를 제공하므로 새 형태를
늘리지 않았습니다. `ContentList`·`DataList`·`MasterDetail` 사이에서
작업·파일의 제목·설명·메타 정보와 개별 작업을 반복 배치하는 용례가
남아 있어 `ItemList`를 선택했습니다. 목록을 매번 직접 조립하지
않고 panel/plain, comfortable/compact 디자인을 고를 수 있습니다.

구현은 `pydemia/ui` 원본 React·Tailwind·native list입니다. 새 runtime
dependency나 외부 component 코드·디자인 자산은 없습니다. 제목 링크와
뒤쪽 작업을 분리하고, 중복 ID·빈 제목·위험한 URL scheme을 거부합니다.
caller가 상태·작업을 소유합니다. 문서 preview에는 작업 재요청과
표시 전환을 연결합니다. 공개 API와 동작 규칙은
[design-contract](../research/design-contract.md)에 기록했습니다.

착수 시 공개 수량은 134개 component·136개 registry item·63개
snapshot이며 Goal 관리용 추정은 약 98%입니다. 로컬
`npm run typecheck`, 대상 테스트 3/3과 전체 UI 테스트 226/226이
통과했습니다. Chromium preview에서
390px·1280px의 page overflow 없이 panel/plain·comfortable/compact
전환을 확인했고, `다시 실행` 버튼 뒤 상태가 바뀌었습니다. Vite 오류
overlay는 없었습니다. 실제 screen reader 발표는 실행하지 않았습니다.
`npm run build`와 `npm run registry:release-check`도 통과했습니다.
registry 검사는 135개 export/catalog와 137개 item·provenance의
대응을 확인했습니다. 64번째 snapshot
`sha256-c0dd57341ba10ac7bd2b885ffe6b9506b55444ad372f4ac9990ee54a20a63835`를
생성하고 배포용 복사본과 현재 registry를 대조했습니다. 고지는
commit `0385db4d490ebfb73049a2384a5139325fe24539`의 provenance와
SHA-256으로 고정했습니다. 로컬 후보는 135개 component·137개 item·
64개 snapshot입니다.

PR #110을 `837a6a29b3b5725c599247b2150e7a06800d14af`로 `main`에
병합했습니다. PR Verify UI run `37068233831`과 `main` Verify UI run

preview는 성공했으나 production 빌드는 `build-rate-limit`로
