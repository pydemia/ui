## Ranked CSS hooks for the owning implementation

1. **High: reusable panel/surface adapters.** In the non-Basic scope, target explicit component roots and their painted slots: `carousel`, `board`, `file-upload` rows, `message`, `conversation`, `citation-list` items, `artifact-viewer`, card variants of `reasoning`/`tool-call`/`agent-status`, `model-selector` panel, `snippet`, `code-block`, `diff-viewer`, `log-console`, `log-viewer`, `terminal`, plus `json-viewer[data-variant="frame"]`. Apply tokenized `--panel-radius-material`, `--panel-border-style`, `--surface-fill`/`--surface-image`, and `--card-decoration` to actual outer painted surfaces. Avoid one broad `[data-ui]` descendant rule because several components use divs for text/data and nested independently themed pieces.
2. **High: media frame and empty/loading placeholders.** Add hooks for image frame, lightbox image/thumbnail, crop viewport and dropzone. Use radius/border material tokens for the frame, and surface tokens for placeholders; leave `<img>` pixels untouched. Keep Dropzone's dashed state and accent drag state.
3. **Medium: local pieces that inherit control materials.** Carousel indicators, Board category chips/selected row, model capability chips, file actions, and LogViewer filter actions should use control/selection tokens where they are interactive; preserve selected and status state colors.
4. **Medium: code/log content shells.** Fenced Markdown, Snippet, CodeBlock, code editor, diff, logs, terminal and JSON should share material treatment only on their frame/header/gutter/empty background. Preserve syntax colors, +/- diff fills, severity levels, terminal status colors and monospace metrics. Avoid painting all code content with a bright accent.

Existing CSS already covers `block-editor[data-appearance="panel"]`, `approval-card`, `prompt-input`, `code-editor` and `markdown-editor` (see [design-modes.css:893-929](../packages/ui/src/design-modes.css)). Do not duplicate those rules; `block-editor` inline appearance and `code-editor` flat appearance remain deliberate variants.

## Suggested contracts for the owner

- In every non-Basic mode, a representative surface root should resolve its radius, border style, fill/image and shadow from that mode's material tokens; Basic should retain component defaults. Ensure rules stay within the `@scope` boundary so a nested Basic scope is not restyled.
- Preserve named variants: Reasoning/ToolCall/AgentStatus inline variants keep their left rail, code-editor flat remains flat, JSON frame remains optional, and media frame remains optional.
- Preserve state/data contracts: Board selected row, Dropzone dragging, Message speaker border, model selection, approval status, AI streaming/completion, progress, error/success, log severity and diff added/removed lines keep their native color/meaning.
- Preserve media and code: actual image pixels are unchanged; placeholders can inherit surface materials. Code/log/JSON keep monospace text, syntax/status colors, contrast and overflow behavior.
- Visually check catalog initial states for Material, Glass, Retro and Terminal against Basic; include the 39 mode/appearance combinations owned by the root audit rather than assuming one material represents all modes. Exercise loading/empty/selected/dragging/expanded/disabled states where the preview offers them. No source/build/browser verification was performed in this audit leaf.
