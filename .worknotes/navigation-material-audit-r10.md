# Navigation material audit R10

## Scope and result

Read-only audit for Tree, TreeNav, GlobalNav/SideNav/BottomNav, AnchorNav, NavigationMenu, TreeSelect, the material-mode stylesheet, and the live catalog examples. No product files, build, Git, deployment, or browser state were changed or inspected. The requested material gap is structural: design modes style generic controls, cards, overlays, app chrome, and tables, but provide no component-level hooks for these navigation rows. Current utility classes then paint selected/current states directly, and some components paint an opaque surface on the root.

## Evidence and specific gaps

- `packages/ui/src/components/tree.tsx:284-296` renders each visible node as a generic flex row. The root treeitem has no stable component hook; the inner row has no semantic hook or state attribute. Its selected background is a literal `color-mix(in_srgb,var(--accent)_12%,transparent)` plus fixed `font-medium text-accent`; hover is fixed `hover:bg-surface-subtle` (`:291-295`). The root is fixed to `rounded-sm border border-border bg-surface p-[var(--space-2)]` (`:345-349`). These leave selection, row border/radius, hover and the enclosing material untouched by mode tokens. The disclosure glyph is embedded in a generic span (`:304-317`), so there is no separate style seam for a branch control.
- `packages/ui/src/components/tree-nav.tsx:150-163` applies fixed surface-subtle hover, fixed rail left border as active marker, and fixed filled accent background. The rail marker violates the approved no-new-inline-start-stripe rule. Links/current-path/ancestor status are not exposed as component-specific hooks; `aria-current=page` and `data-variant` do exist and should remain the semantic state selectors. Disclosure buttons have generic classes (`:188-201`), and nested lists use a fixed left border plus left margin/padding (`:208-214`). Root nav only exposes `data-variant` (`:223-229`).
- `packages/ui/src/components/navigation.tsx:31-47,70-88,100-115,135-153` shows the same pattern across navigation: global and side current treatments are hard-coded utilities; side `rail` uses an inline-start border (`:75-82`); BottomNav paints `bg-surface` on its root (`:101-114`) and hard-codes current/hover colors on links (`:137-146`). The root has `group/bottom-nav` and `data-appearance`, which are useful existing hooks, but there is no `data-ui` identity for material scoping. Prop forwarding already preserves `aria-current` and should stay intact.
- `packages/ui/src/components/anchor-nav.tsx:145-153` exposes `data-variant` only on the root and gives rail a fixed border. Each link is generically styled; rail current uses a left border stripe and accent text; inline current uses fixed accent fill/foreground (`:179-194`). Keep `aria-current=location`, native hash links, depth indentation, scroll state, and `data-variant`; route visual treatment through scoped material selectors.
- `packages/ui/src/components/navigation-menu.tsx:21-33,36-57,60-99,102-127` hard-codes generic menu geometry and surface treatment. Content alone has `data-ui=overlay-panel` and is already picked up by the common overlay material rules (`:400-406` of `design-modes.css`). Triggers and links have no stable `data-ui`/slot hooks; they use fixed hover/open/active background utilities. Add hooks to trigger, content links, and root/list only if the menu is included in the requested Navigation scope. Preserve Radix state attributes and behavior. The existing overlay-panel treatment is already a useful material seam.
- `packages/ui/src/components/tree-select.tsx:148-176,183-189` wraps Tree in a Popover. Its trigger and clear button have fixed border/surface utilities; `Tree` is reused inside the popover and explicitly receives `className="border-0 p-0"`. A root-level tree material rule must account for this embedded presentation so the popup remains coherent and does not gain a second frame. Prefer a `data-context="select"` or a narrowly scoped TreeSelect parent hook only if needed; no public props need to change.
- `packages/ui/src/design-modes.css:3-81` resets material variables at every `[data-design]`; modes define usable materials such as glass/fluent surface fill and image, material rail fill, neumorphic control decoration, retro/decorative borders, terminal dashed borders, and drawn panel radius (`:85-288`). Generic selectors currently cover controls, cards, headings, overlays, chrome and tables (`:337-463`), but no navigation component rows. The existing scope at `:529-530` is the right boundary: `@scope ([data-design]:not([data-design="basic"])) to ([data-design])` prevents the outer scope from styling a nested Basic or independent design scope. Place new nav rules inside this scope and use low-specificity `:where(...)` selectors. Avoid global `[data-design]` descendants, which could leak through nested scopes.
- ThemeScope itself creates both a themed element and a separately themed portal host (`packages/ui/src/components/foundation/theme-scope.tsx:24-29,39-54`). The audit found no need for public API changes: component hooks plus scoped CSS let the existing theme inheritance work in either ordinary content or portaled TreeSelect / NavigationMenu content.

## Minimal semantic hooks recommended

Use stable `data-ui` identities for roots and `data-slot` seams for actual painted elements, while retaining all ARIA and existing variant attributes:

- Tree root `data-ui="tree"`; item wrapper `data-slot="tree-item"`; painted row `data-slot="tree-row"` with state `data-selected`, `data-disabled`, and `data-expanded` (or state attributes derived from existing ARIA); disclosure `data-slot="tree-disclosure"`. Keep `role=tree/treeitem/group`, `aria-selected`, levels/positions, focus and IDs unchanged.
- TreeNav root `data-ui="tree-nav"`; row link/button `data-slot="tree-nav-link"` / `data-slot="tree-nav-disclosure"`; list branch `data-slot="tree-nav-branch"`; expose current path as `data-current-path` if it materially helps styling ancestor links. Existing `aria-current=page`, `aria-expanded`, and `data-variant` remain authoritative.
- Navigation roots `data-ui="global-nav" | "side-nav" | "bottom-nav"`; links `data-slot="nav-link"`, BottomNav root keeps `data-appearance`. Existing link variants and `aria-current` remain authoritative.
- AnchorNav root `data-ui="anchor-nav"`; links `data-slot="anchor-nav-link"`; `aria-current=location`, depth and variant remain authoritative.
- NavigationMenu root/list/trigger/content-link hooks only if NavigationMenu is within the visual target: `data-ui="navigation-menu"`, and slots for trigger and links. Content already has `data-ui="overlay-panel"`; retain this.
- Add no public visual props. Component-level data attributes are sufficient CSS seams and maintain backward compatibility.

## Minimal scoped material direction

In the non-Basic scope, make roots and rows consume theme material tokens instead of fixed white-ish values: root uses `--surface-fill`, `--surface-image`, `--surface-filter`, `--panel-border-style`, `--panel-radius-material`, and `--card-decoration` where a panel frame belongs. A row can use `--surface-fill`/`--surface-image` with a restrained border and radius; use a separate tokenized selected fill mixed from `--accent` and `--surface` (not transparent over arbitrary backgrounds) plus `--accent` or `--foreground` text and stronger weight. Let `aria-current` drive current rows and `data-current-path` drive ancestors. Use focus-visible outline/ring as it is today. Mode families should express themselves through existing mode variables: translucency/filter/image for glass/fluent/spatial, elevation for clay/neumorphic/material, hard/double/dashed borders and square geometry for retro/brutal/pixel/terminal/drawn, and quiet/high-contrast surfaces for swiss/editorial/minimal/flat/dark-ui. Avoid adding a left/inline-start selected stripe anywhere, including `rail` variants; use background, text, weight, and focus.

The TreeSelect embedded Tree should opt out of the standalone frame via its existing `border-0 p-0` or a dedicated presentation hook, while keeping row-level selected material. BottomNav `bar` can retain a flat bar root and use material surface treatment on destinations; `dock` can combine its existing floating silhouette with mode decoration. NavigationMenu Content’s existing overlay material should remain its frame; materialize trigger and content link states without applying a competing panel frame.

## Behavior contracts to preserve

- Tree: public props unchanged; keyboard roving focus, Home/End, arrows, typeahead, Enter/Space select, expanded IDs, lazy loading one request at a time, error retry, disabled ancestors, ARIA tree levels/position/selection/loading remain intact (`tree.tsx:121-241,257-282`; `tests/tree.test.mjs:13-49`).
- TreeNav: links remain native links; disclosure remains a separate button; current page and ancestor path remain distinct; current route opens its path only in uncontrolled state; controlled expanded IDs remain callback-driven (`tree-nav.tsx:113-140,164-219`; `tests/tree-nav.test.mjs:35-55,78-116`).
- Navigation: hrefs and `aria-current=page` stay on links; variant/appearance remain supported; BottomNav labels/icons and dock/bar behavior remain (`tests/navigation.test.mjs:9-60`).
- AnchorNav: native encoded hash hrefs, `aria-current=location`, depth hierarchy, window/internal scroll roots, offset, end-of-scroll selection, history updates, callback-on-change and no forced focus remain (`anchor-nav.tsx:62-143,154-178`; `tests/anchor-nav.test.mjs:26-39,57-112`).
- NavigationMenu: preserve Radix hover/click/keyboard behavior, Escape close, state attributes and portal behavior (catalog contract at `catalog.tsx:7868-7914`).
- TreeSelect: preserve required validation, native form value/reset, clear behavior, selected path, Tree keyboard selection and focus handoff (`tree-select.tsx:99-123,126-215`).
- Preserve Basic and PRISM, plus the praised Breadcrumb/FormWizard/Timeline/Thread. New rules must stay within the nearest non-Basic ThemeScope and must not target those unrelated components.
